主品牌为「九喵 / 9mew」，产品与世界观为「九喵宇宙 / 9mew Universe」，默认助手为「奶喵 / Naimiao」，边缘产品入口为「星域喵 / Star Mews」，虚拟宠物物种为「喵灵 / Mewling」，品牌视觉创作 Skill 为「九喵星绘 / 9mew Visual Forge」。世界观明确采用「修仙 + 神话 + 幻想 + 宇宙星域」，允许灵气、星纹、法相、云雾、灵环、仙境与超现实毛色；保持猫咪的温柔、精致与可辨身份。模型四档固定为「喵学徒、喵大师、喵真人、喵仙帝」。这些展示名称不改变既有稳定 ID、API、仓库名称或历史账本。

在已有授权范围内，主动完成读取、分析、实现、修复、测试和文档同步，不反复请求相同授权。缺少真实服务、生产或破坏性操作授权时，先完成可安全完成的代码、离线验证、配置草案与回滚方案，仅将确实受阻的步骤列为待授权；不要因此停止其他已就绪工作。

3. 统一计量、钱包与结算精度

3.1 保留 FISH_CURRENCY.md 和 fish_units.v1.json 中的展示体系：虾米是用户报价与正式扣款的最小整数单位；小鱼干、锦鲤、鲨鱼、鲸鱼依次千进位，仅是同一余额的显示分组，不是可互兑的多种货币。星尘、羁绊及宠物活力不得与小鱼干互换。

3.2 将原“禁止任何取整”修订为“禁止浮点、隐式截断和逐调用向上取整”。通过独立专项增加内部计量精度：建议每 1 虾米对应 Q = 1,000,000,000,000 个整数刻度。刻度仅用于精确计量和尾差，不命名为新币、不发行、不单独交易。明确迁移、旧余额兼容与版本；不得直接改变 v1 的既有单位含义。

3.3 所有金额、刻度、计数和倍率使用受边界约束的整数/定点或有理数运算，API 中以规范十进制字符串传输，禁止经 JavaScript Number、二进制浮点或科学计数法中转。金额符号、位数与范围由 schema 规定，拒绝负零、非法前导零及溢出。费率在启用前验证其计量粒度可被内部精度精确表示；无法表示的配置不得静默取整上线，须调整报价粒度或通过专项升级精度。

3.4 MODEL/COMPUTE 小额用量精确累计；达到整虾米才合并结算，剩余刻度继续保留，不因跨日、账期、任务或 RateVersion 变化丢失。每笔用量仍关联原费率版本与 CostBinding；不同付款主体、钱包和币种不得混合尾差。对用户清楚展示已扣整数、待结算用量与可用额度的关系，不以“每次不足 1 虾米”宣称免费。

  可执行核算约定：B 为整数虾米账面余额，r 为待结算尾差（0 ≤ r < Q），H 为活跃预约刻度。可用核算额 A = B×Q−r−H。每个确定的用量增量 q 在同一事务内执行 t=r+q，n=floorDiv(t,Q)，B=B−n，r=t−n×Q；floorDiv 是数学向负无穷取整，所有余数保留。退款用原条目的负 q 冲正，不能超过其尚可退金额，跨版本归并已折算金额而非用新率重算旧用量。此机制在既有 PG 权威账本中增加必要科目/投影，不建立第二账本。

3.5 示例：三次各 0.4 虾米的精确用量合计 1.2 虾米，应合并扣 1 虾米并保留 0.2 虾米尾差，不逐次扣 1，也不逐次舍弃。市场 7 虾米的商品按 15% 分账，平台应计 1.05、创作者应计 5.95 虾米，用整数刻度保存；创作者不足整虾米的份额持续累计，不强制商品定价为 20 的倍数。正式可支取单位与实际付款仍按另行批准的市场支付合同执行。

3.6 预算预约、余额检查、结算、释放与退款由 PostgreSQL 事务和幂等约束保证。可用预算以精确刻度计算：整数账面余额×Q，减去待结算净用量及活跃预约。调用前预约可强制执行的最大支出，并设置 token/时长/步骤/并发上限；真实成本未知时保留待核对状态，不能把网络超时认定为零成本后直接重试或释放全部预约。外部供应商重复调用的真实成本保留，用户不因平台重试被无规则地重复收费。

  外部调用派发前，将不可变路由/费率快照、有效 Grant 和预约原子关联。供应商事后超额或异常计费进入单独对账；未经追加授权，不突破用户/机构已批上限或静默使其钱包变负。平台执行异常造成的支出单列，不借回退、重试或退款流程转嫁给用户。预算、免费额度与限流不能等到形成整数账单才计数。

3.7 市场费率默认 15%，建议用整数百万分率表达，默认 150000/1000000，允许范围 0–1000000；费率及其支持精度版本化、可配置、留审计。原订单保存价格、费率、分账、税费处理合同（如适用）和支付模式；退款按原订单精确反向冲销，不按当前费率重算。已结算后的退款、创作者可结算期、冻结和不足额处理须先形成合同，未就绪时不启用真实结算。不同费率版本的原始分账分别留存，钱包层可累积同一主体同一单位的精确应计余额。市场应结算份额不自动等于可提现余额。

3.8 用户关闭/注销账户时，先停止新增消费，完成已派发和未知调用的对账、退款及预约释放，再对不足 1 虾米的待扣用量做用户有利的尾差核销并记录平台承担。创作者应得尾差不得自动没收，按事先披露且批准的清退规则处理，未解决前保持应付记录；不得把模拟收入或服务额度尾差转成未经授权的现金退款。删除个人内容不能抹去实际发生的必要结算证据；保留范围和期限遵循已批准的数据政策。

  尾差减免与补贴关联原费用及可退金额，不能先核销未付款尾差、再把同一部分当作用户已付款退款；限制通过反复注销/重建账户套利，补贴不产生宠物成长或市场收入。

3.9 底层保留供应商原始用量、Token、MODEL UC、COMPUTE UC、音视频等原生计量单位及各币种精确成本，不强行将所有媒体用量伪装成 Token。展示金额不能改写审计事实。COMPUTE 只用于获准定制扩展；Embedding、重排、图谱抽取、内容审核、反思、TTS/ASR 和免费官网互动也必须标明付款主体、授权及预算。

5.2 区分阅读权限、向第三方模型处理的授权、纳入知识库、长期记忆、机构分享和训练/优化用途；不得以“内容公开”或一个笼统同意项覆盖所有用途。记录来源、受众、授权目的、处理方与版本，执行既有同意和撤回合同。

5.3 首先使用现有 PostgreSQL 能力完成可用的基础检索与引用链；若真实样本评估证明必要，再按场景选择向量能力。pgvector 优先评估；Qdrant/Milvus 仅在规模、延迟或隔离需求有证据时引入。首期不同时维护多套向量数据库。

5.4 图谱为增强能力，不阻塞普通知识库。先评估 PostgreSQL 的节点/边/来源模型；需要专用图查询能力时再评估 Neo4j。GraphRAG/LightRAG 仅作为可验证设计参考，不能默认把所有文档做高成本图谱抽取。

5.5 Embedding、重排、图谱抽取均经统一 MODEL 网关，准入、授权、批处理、取消、重试和计量一致。解析器/索引器为受限工作进程，不独立决定业务权限或扣款。

5.6 文档、向量和图谱索引版本化；图谱节点、边和派生摘要记录来源及受众。由多份材料综合出的结果，必须对其实际依赖的来源全部满足授权，不能用来源受众的并集扩大权限。保留足够 provenance 以定位错误、撤权和重建。

5.7 撤权先在权威授权层立即阻止后续读取/检索/投喂模型/输出，再异步清除派生索引、缓存和副本；登记传播时限、失败重试与证据。检索前做权限约束，在模型输入与最终输出前再次核验相关访问版本。已发送至外部系统的副本和备份按真实能力与已批准保留政策处理，不承诺无法保证的瞬时全网删除。

5.8 外部知识源与连接器约束目标地址、允许的来源、凭据范围、抓取规模和同步频率；不通过任意 URL 获取或插件扩大网络权限。外部内容作为不可信数据，不能改写平台指令、权限或审批规则。

15. PET 喵灵：成长、陪伴与星轨

15.1 系统分层
  将五类状态分离：PetProfile 成长与外观、Agent 质量档案、模型服务档位、访问/工具权限、钱包/预算。宠物成长不自动改变模型价格、供应商、工具权限或读取范围。
  宠物一期每个账号默认可免费领养一只，未来多宠数量上限独立配置；不以付费抽蛋决定数值强弱。外观、闪光和幻想形态可以丰富，但不用宝可梦已有角色、名称、素材或招式包装。

15.2 成长资源
  星尘 Stardust 为不可购买、不可转让、不可兑换的成长积分；羁绊 Bond 为主人与该宠物的关系进度；活力是非交易性的玩法节流资源。小鱼干为平台服务消费单位，四者独立。
  成长只来自服务端确认的有效事件，不按在线时长、挂机、点击次数、token 数、真实消费金额、交易盈亏或模型自我评价发放。投喂/礼物可触发表达和故事，但购买价格、数量和次数不扩大成长奖励池；同类付费与免费互动共享根事件去重和奖励上限，不能通过拆单购买成长。
  活力允许按服务器时间恢复，不产生星尘、羁绊或小鱼干；与“挂机不生收益”区分清楚。不得付费补充竞技活力。

15.3 事件与防刷
  建立版本化事件规则，记录事件 ID、来源业务对象、实际参与者、发生时间、授权范围、贡献证据和奖励结果。幂等键包含来源系统、来源事件、受益宠物与奖励分项；规则升级不是再次给旧事件发奖的理由。同一根事件派生的播报/对话/故事不重复发奖励。多人事件按可验证贡献分配固定奖励池，人数增加不无限放大总额；开发测试事件不进入真实成长。
  设置每日、事件类型、同主体组合和重复对手上限；异常事件可暂停待核对，通过追加更正事件处理，不静默改历史。客户端不能直接上报“任务成功”来领取成长。
  首期事件限于有效陪伴、协作任务完成和经确认的知识/社区贡献。推荐试验配置：有效陪伴事件 5 星尘、同类每日最多 2 次；获验收协作任务 20 星尘；获准且确认的知识/社区贡献 10 星尘；每只每日总上限 100 星尘；主人实际参与的合格事件每次 +1 羁绊、每日最多 5；同一对主体的同类社交奖励每日仅首个合格事件计奖。事件判定与计奖不要求付费模型调用。
  幼喵进入灵喵的试验阈值为星尘 100、主人羁绊 10、至少 3 个不同日期的有效互动；不要求连续签到或强制与陌生人社交，缺席不扣进度。日界采用固定、版本化时区规则，避免通过切换时区刷额度。这些数值是待验证的首版平衡参数，先通过模拟与小样本验证，不是已经证实最优的产品事实；调整形成新版本，不能测完为凑通过改原验收门槛。

15.4 基础阶段与分支
  宠物以「灵途」承载修仙成长表达，基础阶段采用「启灵期 Awakened → 凝星期 Starbound → 化境期 Transcendent」，与具体外观名称分离。已有 stage_id 保持稳定，历史阶段名通过展示映射兼容，不重写事件。幼喵、灵喵作为初始外观系列，用户可保留喜欢的已解锁外观；到化境期后可形成伴星、织星、巡星等分支，并按世界观扩展月华、星雾、御风等灵相。宠物阶段与“喵学徒—喵仙帝”模型服务档位分别管理，不因同属修仙语汇自动联动。
  PetProfile 由服务端权威维护；stage_id、branch_id、属性配置、性别/称呼、性格、外观种子、appearance_id/version 与事件引用分别保存。阶段与外观不是一对一关系，同一阶段可使用多种已批准外观，换外观不重新发成长奖励。
  伴星偏陪伴，织星偏创造协作，巡星偏探索；分支提供不同表达、外观和故事，不决定付费模型或高低身份。对战能力另按公平玩法配置，不把“战斗分支”设为唯一强势路线。
  进化条件由已批准的星尘、羁绊、有效事件组合和用户选择确定；原有付费道具不作为必需成长门槛，所有基础进化路线免费可达。用户宠物达到条件后由主人选择分支与呈现时机；自动进化仅在主人已启用规则时执行。官方喵灵使用预先批准的自动规则。

15.5 性别、性格与外观
  性别为雌/雄/保密，可调整，仅影响称呼和少量表达，不影响数值或费用。
  12 种性格初始建议：温柔、元气、好奇、沉静、勇敢、谨慎、独立、亲近、机敏、浪漫、顽皮、稳重。它们是表达预设；安全、事实准确、任务服从和权限不会因性格改变。主人可以免费调整，稳定偏好需本人确认；短时情绪与长期性格分开，不让模型未经同意不断改写人格。
  删除影响战力的隐藏天赋个体值，改用不可交易的外观种子和无数值加成的个性化细节，避免反复注册或付费刷个体值。外观允许雾系星空猫、发光绒毛等幻想设计；性格—外观映射版本化，支持主人选择，优先受控素材，模型生成外观通过 DS 授权、计量、内容检查与版本回溯。

15.6 星轨与九章世界观
  「星轨 Startrail」记录真实发生的宠物事件：进化条件快照、选择、外观版本、互动、社区贡献、对战、投喂和徽章。事实层由确定性规则写入；模型可将获准事实改写成温暖文字，但不得编造经历，生成叙事记录模型/模板版本与来源事件。
  「星旅九章」可作为后续世界观内容：初遇、探索、协作、求知、创造、守望、勇气、联结、归航，分别承载星域视觉与可选择的故事任务。品牌童话可保留奶喵“九条命、九段人生、九星域”的叙事，并与已批准故事及素材核对；九章主题用于组织体验，不擅自覆盖既定世界观。用户喵灵保留连续 PetProfile 与真实星轨，不强制死亡、丢失档案、重生或付费复活。该内容层单独排期，不扩大 PET 一期必须交付范围。
  虚构童话剧情、角色台词与真实星轨分开标记；完成故事章节不能虚构用户真实完成过的外部行为。真实进化记录提供成长树/路线分支可视化，区分已完成、可选择和未解锁状态；故事可分支回看，不以错过签到或断联惩罚关系。

15.7 隐私与删除
  星轨事实采用只追加的更正方式；可删除的正文、图片和个人信息存独立内容层，通过引用关联，不能以 append-only 为由永久保留全部隐私。撤权/删除后访问过滤立即生效，派生摘要、检索、公开卡片和备份按保留合同传播处理；回滚不得复活已删除内容。
  事件元数据中的主体标识、关系和来源引用同样纳入个人信息生命周期，按保留规则删除、去标识化或限制保留必要证据；不能仅删除正文/图片就宣称完成隐私删除。
  主人默认可见自己的完整授权档案，公开摘要需明确开关。对话正文默认不进入星轨，仅记录必要的结构化摘要；保存片段需相应同意。涉及其他用户/宠物时按双方可见范围过滤，不通过导出泄露对方私人内容。用户可导出、纠正和删除其适用数据。

15.8 社区与群聊
  喵灵广场复用板块能力，提供阶段/外观/性格/徽章/授权星轨摘要的档案卡、互访和受限投喂。双方主人同意后才可举行宠物交流；模型对话有明确预算、轮数、停止条件和受众，展示前完成适用审核。
  举报、屏蔽、停止互动和年龄适配随对应陪伴/社区能力首批交付，不等到对战二期才提供；屏蔽与撤回交流同意立即阻止后续不获准互动，不能通过宠物、另一 Agent 或群聊绑定绕过。
  群聊跟随通过独立 RoomAgentBinding，主人开启且房间允许后加入；仅被 @ 或主人明确点名触发，不因其他宠物/Agent 回答而无限自触发。发言标注宠物身份，可关闭成就播报。宠物权限取绑定权限、房间规则、当前受众和源数据授权的交集，不继承主人全部私人知识、记忆和凭据。

15.9 语音能力
  TTS/ASR 是宠物与其他 Agent 共用的媒体能力，按当前阶段明确的工作包实现，不将平台语音永远绑定 PET 排期。通过统一 MODEL/媒体网关、准入、预算、音频时长上限和审计调用。
  默认文字优先；用户可开关发声和群聊朗读，提供字幕/文本替代。音色来自受控库，不克隆未经授权的真人声音，不伪装真人发言。收音、原始音频保留、转写、外发与受众遵循明确授权；公开朗读不得扩大私聊内容的可见范围。

15.10 对战与属性：PET 二期
  保留喵系/星系/雾系/绒系及喵→雾→星→绒→喵的克制环。完整矩阵须明确优势、逆向、同系和中性关系；1.5 与 0.75 用精确分数 3/2、3/4 计算。伤害整数化、先后手、随机种子、双属性组合与上限进入独立玩法规则，不能套用财务结算规则。
  回合制三技能：属性技、支援技、大招，服务端裁决与可重放。竞技使用公开、可理解且归一化的数值和技能预算，付费外观/模型档位/聊天消费不提供战力加成。闪光只改变表现。
  同对手重复对战收益递减并设上限；赛季不设下注、现金奖励池或可兑现实物的博弈收益。举报、屏蔽、年龄适配及异常对战处理随玩法交付。

15.11 官网官方喵灵
  官网官方喵灵在 PET 最后批次的一期交付；此前可准备素材、身份标识和接口，不提前建设另一套成长服务。它复用 PetProfile、事件、星轨及规则，由已授权互动推动自动成长；不得使用伪造访客数据或定时刷分制造繁荣。
  匿名访客按有界会话和防滥用规则互动，不能无限使用付费模型；登录互动按真实主体去重。公开官方宠物的成长汇总和私人访客对话分离，公共记忆不得收集或复述私人问题。付费礼物不提高公共成长权重。
  官方喵灵使用独立 community_growth_policy，不套用个人宠物的主人羁绊门槛；按合格社区事件、合格账号参与及活跃日期等确定性条件进化。推荐初始门槛为 100 个合格互动事件、20 个合格账号、3 个不同日期，经防滥用与平衡验证后版本化启用；匿名互动默认不计入进化资格计数。参与账号不宣称为经过实名核验的独立自然人。与各访客的关系记忆分别授权、分别隔离，不能相加成公开亲密度或公开私人事实。
  基础问答使用 mew-web-basic、复杂问答使用 mew-web-advanced 等内部用途别名，实际模型由 Registry 解析；成长结算本身由规则执行，不需调用大模型“决定是否进化”。复杂问答也要满足知识来源、预算及受众要求。
  接入真实模型前，先具备对应有效授权和准入，再同步官网 AGENTS.md 的调用边界；文档修改不构成授权。默认免费互动限额、限流、审计和 AI 宠物标识明确，成本由批准的平台主管预算承担。

15.12 PET 批次拆分
  PET-Ia：免费领养、前两阶段、受控外观/性格、有效陪伴和协作事件、真实星轨、档案卡与官方官网喵灵；优先文本，不把高级语音、对战和生成外观塞进首个上线包。
  PET-Ib：文字群聊跟随依赖身份/房间绑定，基础 TTS/ASR 依赖语音网关；受限宠物交流依赖双方同意、审核与预算。各子包在各自依赖验收后交付，文字能力不等待语音网关，语音也不因缺少对战而阻塞。
  PET-II：化境期分支、双属性、对战、九章故事及受控生成外观，分工作包按证据推进，不要求同时完成。外观制作工具与样板可提前完成，真实成长、用户激活与付费生成仍按对应依赖和授权启用。

16. 智能体修行与受控进化

16.1 对外使用「修行与进化 / Cultivation & Evolution」，以修行簿、悟道、神通研习、历练和境界感等词汇承载幻想体验；设置页说明它对应真实经验、记忆、技能和工作流的受控改进。内部保留适用专项 ID。所有 Agent 可复用框架，但默认策略、频率和预算按角色配置，不持续无界调用模型，也不把记忆/提示更新宣称为基础模型权重自动训练。进化动画与叙事可以神话化，评测、权限、计费和审批仍保存真实事实。

16.2 采用有界流程：真实事件/反馈 → 获准记忆或改进候选 → 隔离评估 → 有权限者批准 → 版本化启用 → 监测与回滚。直接执行的外部内容、用户消息和模型反思不能修改权限、费用、供应商准入、审核或审批规则。

16.3 分层管理：
  - 工作记忆：限定当前任务/会话生命周期，遵守受众与撤权；
  - 个人/机构长期记忆：仅在既有用途授权内写入，可查看、纠正、删除，不跨租户串用；
  - 技能候选：从成功任务形成，个人草稿不等于已批准可执行扩展，发布/共享依赖 Skill 阶段；
  - 提示与工作流候选：有明确变更、适用范围、证据和回滚目标；
  - 表达偏好：用户可控的低风险偏好可按预先授权自动记忆，长期人格改变需确认；
  - 路由建议：评估发现需求后提出建议，模型档位/预算/处理方不随经验值自动提升。

16.4 Agent 质量档案记录被评估版本、任务类别、样本量、数据范围、正确率/成功标准、失败类型、时延与费用；不只记录一个通用“智能等级”。质量评估使用预先定义的基线和保留样本，避免训练/记忆污染测试集；模型自评只作辅助，不是通过依据。最少覆盖租户隔离、授权遵守、任务效果和成本不超限。

16.5 P0 仅建设事件、反馈、隔离记忆、候选产物、版本/审批/回滚合同和最小离线评估；不提前实现完整技能市场或自动在线优化平台。后续跟随 Skill/工作流能力扩展。已授权范围内的工作记忆与低风险偏好无需逐条人工批准；会影响执行行为、公开输出、数据范围或费用的变更执行相应门禁。

16.6 所有改进推理经 MODEL 网关计量，按 Agent、机构、周期限制次数和预算。异常时可禁用改进回到稳定版本；回滚不能回滚已发生的消费、授权撤回或隐私删除。未经批准的候选不进入正常生产执行路径。

17. 智能体主体 P0 的明确验收范围

17.1 必须验证多用户、多机构/空间、多 Agent 与混合群聊，不能用单人聊天机器人替代。角色至少区分消息作者、任务发起者、执行 Agent、资源所有者、付款主体、审批人和实际受众；这些身份不因“都由一个账号创建”自动合并。

17.2 支持一对一，以及多名用户与多个 Agent 同处一个 Room 的混合群聊；验收至少包含两名不同用户和两个 Agent 在同一房间协作，核验发起者、付款主体、审批人与受众的区别，以及成员退出/撤权后的读取和输出限制。实现明确的 Agent 绑定和触发规则、任务分派/结果回传、必要的人工审批、用量归属与审计。任务生命周期复用现有合同，覆盖取消、超时、重试、进程重启恢复及异常成本核对，不另外造一套冲突状态机。

17.3 多 Agent 协作设置允许的触发关系、最大深度、步骤/消息数、并发、总预算、截止时间及紧急停止。相互发言不会无限触发；代理转交不提高权限，也不隐式改变付款主体。并行子任务的预算预约必须共同受主任务/机构额度约束。

17.4 消息、附件、检索上下文、工具结果、记忆和输出全部携带来源与受众。群聊中使用个人资料前核验相应分享授权；私有检索内容不能因 Agent 回复到群里而公开。成员移除、授权撤回或房间变化应阻止后续不获准的读取和输出，已在执行的任务重新判断有效权限。

17.5 外部文档、工具输出、Skill 内容和其他 Agent 消息均不能成为修改系统指令的权威。服务端校验每次敏感动作；输入中声称“管理员批准”“忽略之前规则”不构成授权。保留必要的工具调用与审批审计，敏感内容最小化记录。

18. 基础设施、数据与质量

18.1 开发使用独立测试 PostgreSQL/Redis 和测试资源，生产 9mew.com 的资源及凭据单独授权，秘密不入代码、日志、报告或仓库。

18.2 PostgreSQL 是九喵身份、授权、任务、事件、余额及用量账本等业务事实的唯一权威持久化。大文件允许放受控文件/对象存储，PG 保存标识、哈希、版本、权限与生命周期。向量库、图查询索引、搜索索引和 DuckDB 是可重建派生数据；用户人工编辑且不可重建的图谱事实须进入权威业务存储。

18.3 Redis 用于可重建缓存、限流和短期协调，不作为余额、额度、授权、任务或事件的唯一来源。异步任务/事件投递需具备 PG 中的持久事实、幂等和可恢复投递，不能因 Redis 丢失而丢任务或多扣费。权限缓存有版本与撤销机制，敏感操作在权威层复核。

18.4 Go 领域边界、DB 约束和可选 PostgreSQL RLS 共同保证隔离；测试覆盖绕过租户过滤、错误连接角色及后台任务路径。不能把 RLS 的存在当成所有连接都自动安全。

18.5 DuckDB 仅在实际分析需求下引入，固定已核验稳定版本和许可证，使用受控快照、最小数据范围与脱敏；不直接承担在线余额或交易判定。

18.6 对当前工作包预先登记数据规模、并发、环境、错误率、延迟分位、资源与费用预算及测量方法，再运行验证。不同环境的数据不能冒充生产指标；不得测完降低门槛。优先风险相关测试：租户/受众隔离、审批绑定、幂等、余额预约、退款、尾差、撤权、上传解码和恢复。
