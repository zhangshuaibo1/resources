九喵 · 追鼠与追蝶网页动画制作提示词 v1

【任务】
为九喵官网和产品网页制作一段可嵌入的 2D 宠物追逐动画，并交付全部原画、透明动画、网页源码、离线预览、生成记录、使用说明和验证结果。实际完成的所有内容同步上传至 https://github.com/zhangshuaibo1/resources 。本场景作为 9mew-chase-motion-v1.0.0 独立版本交付；此前完整业务提示词 v5 保持不变，不用本场景提示词替换业务 PRD。

【形象权威与风格】
先读取现有 9mew-visual-forge Skill 和仓库 AGENTS.md，再查看 refs/mewling_master.png。这个原始奶喵形象是唯一主角身份参考；其 SHA-256 为 2e20839bcda5c5208de4a30654e6e09dcb541076e35c9ef00421c09857319b6a。
保留奶油白细腻绒毛、宽圆脸颊、灰棕色大眼睛、短口鼻、粉色耳内、紧凑身体与蓬松尾巴，以及樱花粉围巾和小金色四角星扣。采用精致柔和的 2D 插画，保持毛发边缘、布料、眼神和优雅姿态；不把原角色重画成简单几何图形，不用未经认可的 3D 模型作参考。3D 暂缓，优先保证 2D 形象和动作质量。
配角小老鼠是友好圆润的小体型灰褐绒毛鼠，奶油色口鼻、粉色圆耳、细尾巴；蝴蝶为轻盈淡紫与粉蓝翅膀，少量暖桃色和柔和金色纹理。配角与猫咪共用细腻材质和柔和光照，角色大小应有清晰层级。生成的图像本身不放文字、水印、网格、背景色块或运动箭头。

【必须实现的路线】
1. 奶喵从屏幕右下角开始。小老鼠在前方出现，奶喵跟着它从右下角跑到左下角。
2. 小老鼠离开视线，奶喵停步、抬头，看见左下方的蝴蝶。
3. 奶喵先蓄力再跃起，追随蝴蝶沿屏幕左侧从下方向上移动。
4. 蝴蝶继续带路，奶喵从左上方移动到右上角。
5. 沿右侧平滑下降回到右下角，收爪、缓冲落地并休息。
追逐采用九喵宇宙的轻盈幻想关系：空中可有伸爪、轻划前爪、尾巴跟随等动作，不需要符合真实猫咪只能在地面行走的限制，但身体结构和朝向必须清晰自然。不要让角色倒立滑行、瞬移、穿越边界或把整幅静态图上下平移冒充肢体动画。

【源动作与计数】
制作 7 个独立源序列：chase-run、chase-look-up、chase-leap、chase-float、chase-land、mouse-run、butterfly-flutter。每组 8 个实际变化的姿态，合计 56 个原始姿态。猫咪和老鼠以一致的向右侧面或四分之三视角为基准，网页向左运动可水平镜像。
rest 从落地尾段复用，明确标记为派生状态；左右镜像、换底色、不同文件格式、重复播放和新标签都不能计为新增独立动作。
每组原始 PNG 图采用 4 列 × 2 行、真实透明背景和足够空白间距，保留完整耳朵、尾巴、爪子和触角。即使生成结果存在网格位置偏差，也要以实际图像内容对齐并记录真实裁切区域，不得靠假造缺失肢体修补。

【创作与组装方式】
用当前可用且获准的生图工具创作新的角色姿态，明确每张参考图的身份参考、风格参考或编辑目标角色。先检查源图，必要时进行有限、针对性的修正。
代码只负责透明分帧、锚点对齐、同尺度布局、动画编码、精灵图集、预览和网页播放。不要程序化粗糙重绘猫脸、用叠化残影假装中间帧，或把源图质量差的问题用高帧率指标掩盖。
猫咪透明 WebP 分帧为 512 × 512，配角分帧为 256 × 256。尽量以身体、落脚点或胸部锚点稳定对齐；蝴蝶不要随着翅膀展开而改变身体位置。镜像和裁切保持 alpha 细节。深浅主题共用同一套透明角色原画，在需要时只改变背景和页面配色。
交付 8 个可用状态各自的透明动画 WebP、浅色 GIF、深色 GIF，共 24 个单独动画导出。另提供完整路线深浅 MP4/GIF 和静态总览；标明这些视频是演示预览，真正网页移动使用透明精灵与播放器。

【网页实现】
默认完整路线约 27 秒，可调速度和猫咪尺寸。使用清晰的阶段状态和连续曲线计算位置；序列帧负责跑动、抬头、起跳、空中跟随和落地，位置插值负责屏幕移动。优先清晰连贯的角色表现，而不是装饰粒子数量。
默认播放有限的一轮后停留在右下角，重复次数和无限循环必须显式配置。提供暂停、续播、重播、停止、销毁和时间点跳转。遵循 prefers-reduced-motion：自动播放时优先静态回退，用户主动选择播放可触发该次动作。页面隐藏、受限容器离屏时暂停调度；组件卸载时清理动画循环和监听器。
画布或动画层不拦截正文、按钮及页面滚动。考虑窄屏、短窗口、窗口缩放和角色安全边距，避免裁断尾巴、触角或爪子。可支持全视口和指定容器两种模式。
提供缺失资源和无效目录的静态原始奶喵回退；失效回退不算完成对应动画。实际生产接入不得假称已完成后端问答、成长、支付或业务功能。
导出实际且可复用的 API 与使用例子，文档以源码为准，不虚构参数或路径。独立 OPEN_ME.html 必须可以离线打开；开发用 ES Module 演示可以通过本地 HTTP 服务运行，并明确两者用途。

【验证与状态】
检查每张源图、每个分帧和实际定时播放：形象一致、肢体清晰、无额外脚或尾巴、无裁切、尺度稳定、转场合理、蝴蝶翅膀开合可读；在浅色和深色背景及实际网页尺寸下检查。
解码验证真实帧数、非重复帧、透明通道、尺寸、时长与循环行为。验证路线顺序、边界、暂停/重播、减少动态效果、隐藏页面/离屏、资源回退、移动端和清理逻辑；记录已执行检查与尚未执行检查。不要把技术检查通过当作用户已经认可视觉效果。
交付默认标记为 2D 关键帧动画候选；说明较大动作可能有帧间切换感，不承诺骨骼动画或 60 fps 新绘制原画。当前不需要 3D 文件。
